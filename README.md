# 메모리룸(MemoryRoom) — 1단계: 기초 셋업 & 데이터 구조

이 폴더는 PRD 5단계 가이드의 **1단계**에 해당하는 코드입니다.
목표: 앱의 뼈대가 뜨고, 데이터를 저장할 D1 데이터베이스 테이블 5개가 만들어지는 것.

---

## 폴더 구조

```
memoryroom/
├── src/                  ← 브라우저에서 실행되는 화면(프론트엔드) 코드
│   ├── main.jsx          ← 앱 시작점
│   ├── App.jsx           ← 화면 라우팅(주소별 화면 연결)
│   └── pages/Home.jsx    ← 1단계 확인용 첫 화면
├── functions/api/rooms.js ← 서버에서 실행되는 API 코드 (D1 데이터베이스 조회/저장)
├── schema.sql            ← 데이터베이스 표(테이블) 5개를 만드는 설계도
├── wrangler.toml         ← Cloudflare 배포/데이터베이스 연결 설정
└── package.json          ← 이 프로젝트가 필요로 하는 패키지 목록
```

> **용어 설명 — "Functions" 폴더**: `src` 폴더 안 코드는 사용자 브라우저에서 실행되고,
> `functions` 폴더 안 코드는 Cloudflare의 서버에서 실행됩니다. 데이터베이스 비밀번호나
> 연결 정보처럼 사용자에게 노출되면 안 되는 작업은 항상 `functions` 쪽에 둡니다.

## 처음 실행하는 순서

### 1) 패키지 설치
```bash
cd memoryroom
npm install
```

### 2) 화면만 먼저 확인해보기 (DB 연결 없이)
```bash
npm run dev
```
브라우저에서 `http://localhost:5173` 접속 → "React 앱이 정상적으로 실행되고 있어요" 문구가 보이면 성공.
(이 시점엔 D1 연결 부분은 "⚠️ 아직 D1 연결이 안 되어 있어요"라고 나오는 게 정상입니다)

### 3) D1 데이터베이스 만들기
기존에 다른 앱들을 배포하실 때처럼 Cloudflare 계정으로 로그인이 되어 있어야 합니다.

```bash
npx wrangler login
npx wrangler d1 create memoryroom_db
```

이 명령을 실행하면 터미널에 아래처럼 나옵니다.
```
database_id = "1234abcd-....."
```

→ 이 값을 복사해서 **`wrangler.toml` 파일의 `database_id = "여기에..."` 부분에 붙여넣으세요.**
(파일 위치: 프로젝트 최상위의 `wrangler.toml`, 6번째 줄 근처)

### 4) 테이블 5개 만들기 (schema.sql 실행)
```bash
npx wrangler d1 execute memoryroom_db --file=./schema.sql
```
성공하면 `User`, `Room`, `Pin`, `Anchor`, `ReviewLog` 5개 테이블이 만들어집니다.

### 5) DB까지 연결된 상태로 실행하기
```bash
npm run build
npx wrangler pages dev ./dist
```
다시 `http://localhost:8788` (wrangler가 안내하는 주소) 접속 →
"✅ D1 데이터베이스 연결 성공! 현재 저장된 룸 개수: 0개" 문구가 보이면 **1단계 완료**입니다.

## GitHub / Cloudflare Pages 배포 (기존에 하시던 방식과 동일)

1. 이 폴더를 GitHub 새 저장소에 push
2. Cloudflare Pages 대시보드에서 해당 저장소 연결
3. Pages 프로젝트 설정 → D1 데이터베이스 바인딩 추가 (`DB` = `memoryroom_db`)
4. 빌드 명령어: `npm run build`, 출력 폴더: `dist`

## 이번 버전에서 지키는 원칙

- **암기 내용은 항상 사용자가 직접(텍스트 또는 음성으로) 입력합니다.** 외부 API가 자동으로
  내용을 채워주는 기능은 이번 버전에는 넣지 않습니다.
- 1단계에서는 실제 콘텐츠 입력 화면은 아직 없습니다. "앱이 뜨는지 + DB가 연결되는지"만 확인하는 단계입니다.

## 2단계 — 사진 업로드 + 다중 핀 찍기 (구현 완료)

이제 실제로 룸을 만들 수 있습니다.

**써보는 순서**
```bash
npm run build
npx wrangler pages dev ./dist
```
1. `http://localhost:8788` 접속 → **"+ 새 룸 만들기"** 클릭
2. 룸 이름/카테고리를 적고 **사진 한 장**을 올립니다.
3. 사진 위를 **클릭**하면 번호 핀(1, 2, 3...)이 순서대로 찍힙니다.
   - 찍힌 핀을 **다시 클릭**하면 삭제되고 번호가 다시 매겨집니다.
   - "마지막 핀 취소" / "전체 지우기" 버튼도 있습니다.
4. **"룸 저장하기"** → 룸 상세 화면으로 이동하며, 저장된 사진+핀이 그대로 보입니다.
5. 홈으로 돌아오면 만든 룸이 목록(썸네일 카드)에 나타납니다.

**이번 단계에서 추가된 것**
- 화면: `src/pages/NewRoom.jsx`(만들기), `src/pages/RoomDetail.jsx`(보기), Home에 룸 목록
- API: `POST /api/rooms`(룸+핀 한 번에 저장), `GET /api/rooms/:id`(룸+핀 조회) → `functions/api/rooms/[id].js`
- 사진 저장 방식: 별도 이미지 저장소(R2) 없이, 브라우저에서 사진을 축소(긴 변 1200px, JPEG)한
  뒤 `Room.imageUrls`에 data URL로 저장합니다. 핀 위치는 사진 크기에 상관없도록 **0~1 비율**로 저장합니다.

> 참고: 위 순서는 **로컬 DB**에 저장됩니다. 배포한 사이트(원격 D1)에도 반영하려면
> `npx wrangler d1 execute memoryroom_db --file=./schema.sql --remote` 로 스키마를 한 번 적용해 두세요.

## 3단계 — 핀마다 암기 내용(앵커) 입력/저장 (구현 완료)

이제 각 핀에 실제로 외울 내용을 붙일 수 있습니다.

**써보는 순서**
```bash
npm run build
npx wrangler pages dev ./dist
```
1. 룸 상세 화면(홈에서 룸 카드 클릭)에서 사진 위의 **번호 핀을 클릭**합니다.
2. 아래 편집 패널에서 **암기 내용**을 직접 적습니다.
   - Chrome 등 지원 브라우저에서는 **🎙️ 음성으로 입력** 버튼으로 받아쓰기도 가능합니다.
   - **암기 기법**(숫자변환법/문자변환법/연상기억법/기초결합법)과 **연상 스토리**는 선택 입력.
3. **저장** → 내용이 저장된 핀은 **초록색**, 아직 빈 핀은 **빨간색**으로 표시됩니다.
   상단에 "내용 채움 2/3" 처럼 진행 상황도 보입니다.
4. 이미 저장한 핀을 다시 클릭하면 내용이 채워진 채로 열려 **수정/삭제**할 수 있습니다.

**이번 단계에서 추가된 것**
- 화면: `RoomDetail.jsx`를 인터랙티브하게 확장(핀 클릭 → 앵커 편집 패널)
- API: `GET/PUT/DELETE /api/pins/:pinId/anchor` → `functions/api/pins/[pinId]/anchor.js`
  (PUT은 있으면 수정·없으면 생성하는 upsert 방식). 룸 상세 응답에 핀별 `anchor`가 함께 담깁니다.
- 음성 입력: 외부 API 없이 브라우저 내장 음성 인식(`src/lib/speech.js`) 사용.
  음성으로 입력한 앵커는 `inputMethod = 'voice'`로 저장됩니다.

> 원칙 유지: 암기 내용은 **항상 사용자가 직접**(텍스트 또는 음성으로) 입력합니다.
> 외부 API가 내용을 자동으로 채워주는 기능은 넣지 않습니다.

## 4단계 — 복습(ReviewLog) 화면 (구현 완료)

저장한 암기 내용을 핀 단위로 복습하고 결과를 기록합니다.

**써보는 순서**
```bash
npm run build
npx wrangler pages dev ./dist
```
1. 룸 상세 화면에서 **🧠 복습 시작하기** 버튼을 누릅니다. (내용이 있는 핀이 1개 이상일 때 표시)
2. 핀이 하나씩 나옵니다. 먼저 스스로 떠올려 본 뒤 **정답 보기**로 내용을 확인합니다.
3. 기억한 정도를 누릅니다: **😵 기억 안 남 / 😮‍💨 어려웠음 / 🙂 보통 / 😎 쉬웠음**
   → 결과가 `ReviewLog`에 저장되고, 아래 규칙으로 **다음 복습일**이 자동 계산됩니다.
   - 기억 못함 → 1일 뒤 · 어려움 → 1일 뒤 · 보통 → 3일 뒤 · 쉬움 → 7일 뒤
4. 마지막에 **성공/실패 요약**과 핀별 다음 복습일이 나옵니다. "다시 복습"도 가능합니다.
5. 룸 상세에서 각 핀을 다시 열면 **최근 복습 결과·다음 예정일**이 표시됩니다.

**이번 단계에서 추가된 것**
- 화면: `src/pages/Review.jsx`(복습 세션), 라우트 `/rooms/:id/review`, 룸 상세에 복습 버튼·최근 복습 상태
- API: `POST /api/anchors/:anchorId/review`(복습 기록 + 다음 복습일 계산), `GET`(복습 이력)
  → `functions/api/anchors/[anchorId]/review.js`. 룸 상세 응답의 각 앵커에 `lastReview`가 함께 담깁니다.
- 간격 반복(spaced repetition)은 서버에서 계산합니다. (위 4번 규칙)

## 5단계 — 학습 통계 대시보드 + 배포 마무리 (구현 완료)

**① 학습 통계 대시보드**

홈 화면의 **📊 학습 통계** 버튼(또는 `/stats`)에서 학습 현황을 한눈에 봅니다.
- 🔥 **연속 복습 일수** — 오늘(또는 어제)부터 하루도 안 빠지고 이어진 날 수
- **복습 예정** — 다음 복습일이 오늘까지 도래한 항목 수
- **오늘 복습 / 정답률 / 새 항목(아직 복습 전) / 총 복습 수**
- 만든 룸 수, 저장한 암기 항목 수

> 이 앱은 아직 로그인이 없어 통계는 **DB 전체(1인 사용) 기준**으로 계산합니다.
> 나중에 로그인이 생기면 각 쿼리에 `userId` 필터만 더하면 됩니다.
> API: `GET /api/stats` → `functions/api/stats.js`

**② 배포(GitHub → Cloudflare Pages) 체크리스트**

1. 이 폴더를 GitHub 새 저장소에 push (`node_modules`, `dist`, `.wrangler`는 `.gitignore`로 제외됨)
2. Cloudflare Pages 대시보드에서 저장소 연결
   - 빌드 명령어: `npm run build`
   - 출력 폴더: `dist`
3. Pages 프로젝트 설정 → **Functions → D1 데이터베이스 바인딩** 추가: `DB` = `memoryroom_db`
4. **원격(프로덕션) D1에 스키마 적용** (로컬에서 한 번만):
   ```bash
   npx wrangler d1 execute memoryroom_db --file=./schema.sql --remote
   ```
5. 배포 후 사이트 접속 → 룸 만들기 → 핀 → 암기 내용 → 복습 → 통계까지 동작 확인

## 완성! 🎉 전체 사용 흐름

1. **홈**에서 "새 룸 만들기"
2. 사진 올리고 → 사진 위에 **번호 핀** 찍기 (2단계)
3. 각 핀에 **암기 내용**을 텍스트/음성으로 입력 (3단계)
4. **🧠 복습 시작하기**로 핀을 하나씩 떠올리며 성공/실패·난이도 기록 (4단계)
5. **📊 학습 통계**에서 연속일수·정답률·복습 예정 확인 (5단계)

> 개선 아이디어(선택): 로그인(사용자 구분), 한 룸에 사진 여러 장, 복습 알림,
> 음성 원본 저장(R2) 등. 필요하면 언제든 말씀해 주세요.

- **예시 이미지 10장** (`public/samples/`): 거실·주방·침실·욕실·현관·사무실·교실·공원·카페·지하철.
  기억의 궁전(장소법)에 맞게 사물이 여러 곳에 배치된 **실사 사진**입니다. (웹용으로 1600px·
  JPEG 압축되어 장당 100~350KB) **새 룸 만들기** 화면에서 "예시 장소에서 골라보세요"
  갤러리를 클릭하면 그 자리에서 룸 배경으로 쓰입니다.
  - 다른 사진으로 교체하려면 [`IMAGE-PROMPTS.md`](./IMAGE-PROMPTS.md)의 프롬프트로 만들어
    같은 파일명(`01-living-room.jpg` 등)으로 `public/samples/`에 넣으면 됩니다.
- **기억법 가이드**: 앱 안 **📖 기억법 가이드**(`/guide`) 또는 저장소의 [`GUIDE.md`](./GUIDE.md).
  장소법 원리, 4가지 기법(숫자변환/문자변환/연상기억/기초결합), 좋은 연상의 원칙,
  복습(간격 반복) 활용법, "조선 왕 순서" 예시 워크스루까지 담았습니다.
